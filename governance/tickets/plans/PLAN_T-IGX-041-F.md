## Problem

1. **The F-35 classification of the evidence-plane audit trail rests on an assumption the code does not enforce (F-D6-01).** `EvidencePlaneSecurityAuditTrail.__init__` (`intergrax/runtime/security/security_audit_trail.py`) stores the injected port unchanged (`self._evidence = evidence_persistence`) and `append` calls `self._evidence.append(event, tenant_id=tenant)`. The COMPAT-X inventory classifies exactly that call site (module path, function `append`, callee `self._evidence.append`) as `CANONICAL_VALIDATING_PATH` (`tests/qualification/compat_x/test_compat_x_event_evolution_f35_security_audit_trail_site.py`, added by T-IGX-040-D). The module docstring of that test says the canonical composition wraps the port in the validating port, but nothing in the trail or in `resolve_security_audit_trail_wiring` (`intergrax/applications/_shared/security_audit_trail_wiring.py`, which passes its `EvidencePersistencePort` argument straight to the class) does. `as_evidence_persistence_port` (`intergrax/runtime/events/evidence_persistence_adapter.py:155`) is the platform normalizer: it returns a `CanonicalRuntimeEventWriteValidatedPort` unchanged, wraps a legacy `RuntimeEventPersistence` in `ValidatingEvidencePersistencePort(RuntimeEventPersistenceEvidenceAdapter(...))` and wraps any other object in `ValidatingEvidencePersistencePort`; `ValidatingEvidencePersistencePort.append` runs `prepare_canonical_production_write_event` and `assert_runtime_event_schema` before delegating. A port that is not a validating port therefore receives the trail's events as built, without that validation (audit probe `A1`); the COMPAT-X rule matches the module path, the function name and the callee text only (audit). Planning-session observation to re-check by the implementer: the ports the existing tests pass (`resolve_runtime_event_persistence(...)`) are `ValidatingRuntimeEventPersistence`, a `RuntimeEventPersistence` subclass that is not a `CanonicalRuntimeEventWriteValidatedPort`, so normalization will wrap them and validate a second time; the implementer proves that this is harmless (events and stored results unchanged) or reports it.
2. **The "immutable, replicated" report is in-process bookkeeping and says more than it proves (F-D6-02).** `MultiRegionSecurityAuditTrail` (`intergrax/runtime/security/multi_region_audit_trail.py`) keeps `_region_entry_ids`, a dict of per-region lists of entry ids in the same process, appends each new id to every list in lockstep and compares those lists with each other and with a sealed prefix of the same lists (`seal_prefix`, `verify_replication`). It never reads the stored entries back and no entry carries a hash chain or a signature; after a process restart the lists are empty. Its module and class docstrings ("Immutable multi-region security audit trail", "Append-only audit trail replicated across configured regions") and the report fields `replicated` / `immutable` therefore read as a storage guarantee. The audit's probe `A2` shows deleting stored rows in the durable evidence plane leaves `replicated=True, immutable=True` (audit). Tamper evidence is a missing feature; the overstating wording is a defect of documentation.
3. **Plugin provenance is bound to the operator's mapping key, not to the attested distribution (F-D6-05).** `PluginProvenanceAdmission._attestation_for` (`intergrax/core/plugins/admission.py`) looks the attestation up by comparing the normalized `spec.distribution` with the normalized *mapping key*; `evaluate` then resolves the installed version of `attestation.distribution` and verifies the signature over `attestation.distribution`. An attestation of another distribution stored under the key of the entry point's distribution is therefore accepted for that entry point (audit probe `PV1`). The class docstring discloses that the installed files are not re-hashed (only the installed version string is compared).
4. **A provider exception, with its text, stays attached to the credential-unavailable error (F-D6-12, LOW, by-product).** `SecretsStoreCredentialResolver.resolve` (`intergrax/integrations/credentials/secrets_store_resolver.py`) raises `CredentialProviderUnavailableError(sanitized message) from exc`; the chained `__cause__` carries the provider's message, which a logged traceback prints. The sibling `CredentialNotFoundError` branch of the same method already uses `from None`.
5. **The sandbox governance-deny unit test is red because it does not bind the governance identity that the invoker requires (F-D6-07).** Reproduced at `1da9ff5e7` with one pytest over `tests/unit/runtime/sandbox/test_cap_c1c_sandbox_evidence_and_contract_purity.py` (13 tests, run without `-x`): 1 failed, 12 passed. `test_c1c_q_governance_deny_zero_physical_execute` runs `RuntimeToolInvoker.invoke` inside `canonical_governed_execution_scope("c1c_gov")` without `governance_tenant_id` / `governance_principal_id`. `canonical_governed_execution_scope` (`testing_support/builder.py`) binds the active execution governance identity only when both are given; without it `record_governance_policy_decision_evidence_for_active_identity` (called at `intergrax/runtime/nexus/tools/invoker.py:749` inside `RuntimeToolInvoker._require_current_attempt_authorization`, reached from `_prepare_invocation` within `invoke`, after the declarative policy decision was evaluated) calls `require_active_execution_governance_identity()`, which raises `RuntimeError("active execution governance identity required")` instead of the expected `DeclarativePolicyViolationError`. Without an active governance identity the invocation is refused with that `RuntimeError` while the invoker prepares it (the traceback of the reproduction ends in `_prepare_invocation`), that is before the tool executor is reached; the planning session did not measure the sandbox audit log in that state, the new negative test does. The test setup is therefore repaired and the refusal is pinned by a new negative test. The physical egress tests of `tests/integration/runtime/sandbox/reference_substrate` are skipped on this Windows host (audit; not re-run by the planning session), consistent with the declared C10/C15 restriction; nothing is changed there.

1. `test_d6_f01_audit_trail_validating_port.py` (F-D6-01). With a recording stand-in port that is not a `CanonicalRuntimeEventWriteValidatedPort`: (a) after construction the trail's port is a `CanonicalRuntimeEventWriteValidatedPort` (fails today: the port is stored unchanged); (b) `append` runs `prepare_canonical_production_write_event` and `assert_runtime_event_schema` before the stand-in sees the event (spy on both; fails today), and when the schema assertion is made to raise the stand-in has recorded nothing and the error propagates (fails today); (c) `resolve_security_audit_trail_wiring` with the stand-in validates both bootstrap events before they reach it (fails today); (d) a port that already is a `ValidatingEvidencePersistencePort` is used as is (no second wrapper); (e) a legacy `RuntimeEventPersistence` (the in-memory event store) is accepted and the entries listed back equal the entries appended (regression); (f) negative: a `None` port raises `TypeError` at construction; (g) the entries listed after a durable restart are unchanged (the existing `test_d6_audit_trail_durable.py` stays green and is part of the Test contract).
2. `test_d6_f02_audit_trail_claims.py` (F-D6-02, relabel). 3. `test_d6_f05_plugin_provenance_binding.py` (F-D6-05). 4. `test_d6_f12_credential_error_chain.py` (F-D6-12). A secrets store raising an exception whose text contains a secret-shaped token: the raised `CredentialProviderUnavailableError` and its whole `__cause__` / `__context__` chain, formatted as a traceback, contain no provider text (the `__cause__` part fails today); `CredentialNotFoundError` and `CredentialScopeMismatchError` behaviour is unchanged.
