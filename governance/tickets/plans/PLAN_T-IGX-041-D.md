## Problem

The D4 mechanisms (engine, instance guard, supervisor, metrics, public API manifest) are real and narrowly tested, but five defects exist in code that is already composed, one gate cannot see the change it is meant to catch, the cited documentation contradicts the code in two places, and three D4 unit tests are red on a Windows account without symlink privilege:

1. **Task cancellation skips all rollback (F-D4-01, MEDIUM).** `HostedApplicationEngine.start` wraps `_startup_sequence` in `except Exception` (`engine.py:252-265`). `asyncio.CancelledError` is a `BaseException`, so `_startup_failure_cleanup` never runs. `run_until_stopped` (`engine.py:295-299`) has no cleanup path, and `HostedApplicationSupervisor.run` catches `Exception` only around `engine.run_until_stopped()` (`supervisor.py:192-204`). Reproduced here: cancel during a slow required-component start leaves state `starting`, the lease acquired and not released, the context open, and a second engine on the same run directory is rejected; cancelling `run_until_stopped` on a READY engine leaves state `ready`, runtime and components started, lease not released.
2. **A hung `runtime.ready()` leaves the host reporting ready (F-D4-04, MEDIUM).** `_refresh_health` awaits `self._runtime.ready(self._context)` with no timeout (`engine.py:498-513`) although every component health probe is bounded by its own `health_timeout_seconds` (`components.py:381-383`). Reproduced here: after READY, with `ready()` hanging, `health_snapshot().ready` stays `True`, `health_evaluation_failed` stays `False`, `last_evaluated_at` does not change. The same unbounded call exists in the startup sequence (`engine.py:419`), where a hanging probe blocks `start()` and, through the operation lock, `stop()`.
3. **Downstream publishes are awaited without a bound (F-D4-12, LOW, repaired as a by-product of 1 and 2 because it is the same class: a shutdown or restart that can hang).** `HostingEventDispatcher.publish` awaits the downstream publisher directly (`eventing.py:150-166`). The engine publishes `APPLICATION_STOPPING` (`engine.py:566`), the drain-duration metric (`engine.py:636-639`) and the exit-class metric (`engine.py:741`) outside `run_bounded_phase`; the supervisor's three safe publish helpers await `self.event_publisher.publish` directly (`supervisor.py:438-523`). Reproduced here: a publisher that hangs on the drain-duration metric makes `engine.stop()` not return within 60 s while the computed shutdown budget is 150 s.
4. **The public-API fingerprint cannot see a contract loosening (F-D4-07, MEDIUM).** `describe_public_symbol` (`public_api.py`) records bases, own public member signatures and, for models, field annotation and `is_required` only. It ignores `model_config`, `Field` constraints and validators, so flipping `extra` from `forbid` to `allow`, or widening `ge`/`le`, leaves the fingerprint and the version gate unchanged (audit probe P2). This is the class of change made to `HostDeploymentProfile` in the same wave.
5. **Documentation contradicts the code (F-D4-09, MEDIUM).** The architecture and the plan describe TL-FIX-C as "ACCEPTED / PLANNED / not fixed" (`TIER3_APPLICATION_ENVIRONMENT.md` architecture lines 27, 47, 171-173, 273, 282, 297, 601, 619; plan line 129), but T-IGX-036-R moved three `lkw_*` keys to a typed `LkwHybridDaemonDeployment`; one key (`business_agents_deploy_enabled`) remains on the generic profile. Three satellite rows (`TIER3_APPLICATION_ENVIRONMENT_embedded_detail.md` lines 11, 12, 60) mark shadow/sandbox lifecycle `Done` without the isolation bound that the architecture and the main plan row state. `APPLICATION_HOSTING.md` still marks the hosting metrics suite (APP-HOST-3D) `Planned` (lines 25, 41, 314, 327) although the six metrics ship (R009 PASS).
6. **No gate pins the "single effective composition root" (F-D4-05, MEDIUM, gate part).** `wire_application_environment` is called by all nine product `host/wiring.py` files, but the lab host factory builds a second tool wiring for MCP (`applications/lab_application/host/factory.py:225` calls `wire_lab_tools`, which calls `build_application_tool_wiring` with a hard-coded tenant `lab`, `tool_wiring.py:101-114`) and nothing asserts that no further second path appears.
7. **Three D4-area unit tests are red on a host without symlink privilege (F-D4-19 (b), INFO, test hygiene).** `test_symlinked_run_directory_rejected`, `test_symlinked_ancestor_rejected` and `test_symlinked_lock_file_rejected` call `Path.symlink_to` and fail with `OSError: [WinError 1314]` (reproduced here: 3 failed, 19 passed in `tests/unit/hosting/instance`). The symlink-rejection code of the guard was therefore never executed on this host.

Re-check of the three points the auditor did not verify (requested by the orchestrator):

- **POSIX lock path.** `intergrax/hosting/instance/_native_lock.py:46-52` takes `fcntl.flock(fd, LOCK_EX | LOCK_NB)` and maps `OSError` to `NativeFileLockError("lock_busy")`; release is `flock(fd, LOCK_UN)`; the file is opened with `O_CREAT | O_RDWR | O_NOFOLLOW`. Read, not executed: this host is Windows. No defect found. The instance tests are marked `unit`, not `gate` (`test_file_guard.py:34`, `test_w3_file_guard_regression.py:36`), and the CI regression runs `tests/unit -m "gate and not no_ci"` (`unit-tests.yml:287`), so no pipeline I could find selects them. This plan therefore adds one platform-independent test of the POSIX branch with an injected `fcntl` (Deliverable 7); it does not claim that Linux or macOS were exercised.
- **Symlink hardening.** Read (`file_guard.py:102-143`, `:416-431`: ancestor and parent symlink checks and an `lstat` check of the lock file) and now covered by Deliverable 6 on hosts where symlink creation is possible; on hosts where it is not, a stubbed complement keeps the branch under test.
- **F-D4-06 (code-read finding).** Re-read and judged not repairable by a bounded change (see "Excluded findings"): the "tenant" and "task" arguments of `HostedSandboxSession` are stored as attributes and never read (`hosted_session.py:44-45`; no consumer in `intergrax/runtime/sandbox` or `intergrax/tools`; `SandboxAuditEntry` has no tenant field), and `SandboxHostBackend.create_session()` takes no tenant. Deriving the label from the composition tenant would change nothing observable.

## Deliverables (tests first, then fixes)

Every new test is written and run red before its fix and the red run is kept under `.tmp/proof/t-igx-041-d/`. New tests live in the new directory `tests/qualification/pdc_x/d4_repair/` and reuse `tests/qualification/pdc_x/d4/_support.py` unchanged. Existing D4 tests stay byte-identical except the docstring edit of Deliverable 8 and the two symlink files of Deliverable 6.

1. **Cancellation (F-D4-01).** Tests first: (a) cancel the task running `engine.start()` while a required component's `start` sleeps: expected afterwards: started components stopped in reverse order, runtime stopped if created, lease released, context closed, lifecycle state `failed`, `CancelledError` propagates, and a second engine on the same run directory starts READY; (b) cancel `run_until_stopped()` on a READY engine: components, runtime and lease released, state terminal; (c) cancel `engine.stop()` mid-drain: the stop sequence still releases the lease before the cancellation is re-raised; (d) cancel `HostedApplicationSupervisor.run()` while READY: `_verify_engine_cleanup` reports a released lease and a closed context; (e) negative control: an ordinary component failure still follows the existing rollback path with the same journal (the existing `test_r003_*` tests stay green). Fix in `engine.py`: `start`, `stop` and `run_until_stopped` handle `asyncio.CancelledError`: run the existing bounded terminal cleanup (or, in `stop`, drive the bounded graceful sequence to completion) under `asyncio.shield`, then re-raise. No dataclass field and no public signature of `HostedApplicationEngine` or `HostedApplicationSupervisor` changes (both are `@dataclass`, so a field would change the manifest fingerprint). The supervisor needs a change only if test (d) shows one.
2. **Bounded readiness (F-D4-04).** Tests first: (a) after READY, `ready()` hangs: within the bound `health_snapshot().ready` is `False`, `health_evaluation_failed` is `True` and a `health_poll_failed` secondary failure is recorded; (b) `ready()` hangs during startup: `start()` fails with `HostedApplicationStartupError`, the rollback runs and `stop()` is not blocked; (c) negative: a fast `ready()` keeps the host ready and a slow-but-within-bound `ready()` is not failed. Fix in `engine.py`: wrap both `self._runtime.ready(...)` calls in `asyncio.wait_for` with `definition.lifecycle_policy.default_blocking_hook_timeout_seconds` (30 s default). No new public policy field is added; the tests use a small `LifecyclePolicy(default_blocking_hook_timeout_seconds=...)`.
3. **Bounded publishes (F-D4-12).** Tests first: (a) a downstream publisher that hangs on every event: `engine.stop()` returns within the bound, records a secondary failure with reason `event_publish_timed_out`, and still releases the lease; (b) the supervisor with a hanging publisher completes `run()` and its restart path; (c) negative: a publisher that returns promptly still receives every event in order and all six metrics. Fix: `HostingEventDispatcher.__init__` (not exported) gains an optional timeout argument; the engine passes `definition.lifecycle_policy.default_observer_hook_timeout_seconds` (5 s default); the supervisor's three safe helpers bound their `publish` calls with the same policy value. The bound is not charged to the global shutdown budget.
4. **Strengthened fingerprint (F-D4-07).** Tests first: (a) two models with the same annotation and different `extra`, `ge`/`le` or validator names get different fingerprints; (b) the fingerprint of an unchanged symbol is identical across two computations; (c) flipping `HostedApplicationProfile.model_config["extra"]` in a copy changes its fingerprint; (d) `HOSTING_PUBLIC_API_VERSION_HISTORY["1.0.0"]` still equals the recorded literal `sha256:88814bef45fe1494f1a2a5d22165c932063eba8a77df96db83bf59efb9134907` (history is never edited). Fix in `public_api.py`: `describe_public_symbol` adds the canonical `model_config`, per-field constraint metadata and validator names. Because every model fingerprint then changes, the declaration is regenerated (`uv run python -m intergrax.hosting.public_api`), the version becomes `1.0.1` and a `1.0.1` history entry is added (a patch: no symbol is added, removed or changed in behaviour; the gate cannot tell a scheme change from a surface change, which the module docstring will say). The implementer must confirm that the fingerprints are reproducible under the locked pydantic version.
5. **Composition-root gate (F-D4-05).** Tests first, as a pure checker over source text with synthetic negatives: (a) each of the nine `applications/*/host/wiring.py` calls `wire_application_environment`; (b) no `applications/*/host/wiring.py` or `host/factory.py` calls `build_application_tool_wiring` or passes `conformance_check=False`; (c) a function imported from a product `host/tool_wiring.py` into a `wiring.py` or `factory.py` is allowed only for the declared exceptions, which hold exactly one entry (`lab_application/host/factory.py` importing `wire_lab_tools`, MCP path), with the reason and the reopen condition from this plan in the test; (d) the exception is still used (a stale exception fails). Negative tests prove that a second call, a `conformance_check=False` and an undeclared import are detected.
6. **Symlink tests (F-D4-19 (b)).** In `test_file_guard.py` and `test_w3_file_guard_regression.py` a small helper creates the symlink and calls `pytest.skip` with the reason "symlink creation not permitted on this host" only when `OSError` is raised by the creation. New stubbed complement tests (in `d4_repair/`) patch `Path.is_symlink` / `os.lstat` results so the ancestor, parent and lock-file rejection branches run on every host. The rejection assertions of the existing tests are unchanged.
7. **POSIX lock branch.** One test with `sys.platform` patched and a fake `fcntl` module injected into `sys.modules`: `try_acquire_exclusive` calls `flock(fd, LOCK_EX | LOCK_NB)`, an `OSError` becomes `NativeFileLockError("lock_busy")`, `release_exclusive` calls `flock(fd, LOCK_UN)` and swallows `OSError`. `_native_lock.py` is not edited.
8. **Metrics bridge and crash-test wording (F-D4-13, F-D4-03).** Tests: all six metrics (`start`, `ready`, `degraded`, `drain_duration`, `restart_count`, `exit_class`) survive `ObservabilityHostedApplicationEventPublisher` with an enabled policy and an `InMemoryObservabilityExporter`; the default publisher exports nothing (pins the documented opt-in); a `run_hosted_application(profile, event_publisher_factory=...)` run with the enabled exporter, if it completes without a new public parameter. Docstring: `test_d4_crash_restart_subprocess.py` states that the crash detector is part of the test and that the product supervisor restarts on the exit of its own engine or on a control-plane restart request.
9. **Documentation (F-D4-09, F-D4-13).** `TIER3_APPLICATION_ENVIRONMENT.md` (architecture and plan): TL-FIX-C is recorded as partly implemented (the three `lkw_*` keys moved to `LkwHybridDaemonDeployment` by T-IGX-036-R; `business_agents_deploy_enabled` remains on the generic profile pending the Operator decision of F-D4-08), the A-level text stays A4, and no "A5" claim is added; the key table row of `business_agents_deploy_enabled` stays "Product-owned" with the open note. The implementer re-reads each cited line before editing and edits only statements that the code contradicts.
