## Problem

The B-D2 repairs hold where they were aimed (the auditor killed nine runtime mutants of the D2 guards). Re-reading the code confirms the following real defects in code that already runs, and a red evidence base:

1. **The hard model-window budget counts only `message.content` (F-D2-01).** `classify_candidates` (`context_compiler.py:68-70`), `ContextCompiler._enforce_hard_budget.total` (`:282-283`) and the last-user check (`:295`), `_hard_trim_messages` (`degradation_ladder.py:86`), `apply_degradation_step` `TOKENIZER_HARD_TRIM` (`:265`) and `estimate_mandatory_protected_message_tokens` / `estimate_mandatory_base_message_tokens` (`context/budget/mandatory_base_messages.py:172,191,208`) all size a message as `count_tokens(message.content or "")`. An assistant message with empty content and a 200,000-character `tool_calls[].function.arguments` costs 0, so the "hard window" never trims or drops it. Content-only truncation cannot shrink such a payload either, so the hard trim must also drop whole tool-call groups (or fail closed for mandatory ones) when the non-content payload alone does not fit.
2. **The last-resort hard budget drops the newest messages first (F-D2-17).** `_enforce_hard_budget` iterates `range(len(working) - 1, -1, -1)` (`context_compiler.py:345`) and keeps the stalest history; it contradicts the oldest-first ladder step `TRUNCATE_OLDEST_HISTORY`.
3. **TASK scope of the memory control plane is tenant-blind and ungoverned (F-D2-02, F-D2-14).** `_remember_task` / `_forget_task` (`default_memory_control_plane.py:846-887`) validate scope authorization only; they call `task_memory.write/delete(namespace, key)` with no tenant, identity or governance evaluation (USER scope calls `_enforce_governance`, `:552`, `:765`). `TaskMemoryCapability` (`contracts/memory_control.py:295`) has no tenant. Two tenants sharing one capability overwrite and delete each other's `(namespace, key)`. `_assert_identity_tenant_is_bound_tenant` (`:211-216`) guards only the concrete `UserProfileManagerMemoryCapability`; a replacement capability is unguarded. Latent in the shipped composition (it wires no task memory in `memory_wiring.py`), but `memory_control_wiring.py` accepts a `task_memory` and the harness host wires a task-memory store.
4. **A raising reindex hook breaks retrieval (F-D2-11).** `embedding_version_policy.py` calls every registered hook without isolation; `RetrievalService._assess_freshness` evaluates freshness outside the guarded observer call, so a hook exception turns a successful retrieval into an exception.
5. **The retention sweep task trusts the producer's clock and blocks without a bound (F-D2-13).** `retention_sweep.py:337` takes `as_of` from the payload (a far-future value expires every entry with a validity or policy window; forget is irreversible); `:288-291` joins the worker thread without a timeout, so cancellation and deadlines cannot interrupt it.
6. **The D2-cited RAG evidence is red (F-D2-08, F-D2-09, F-D2-10).** 48 failures and 13 collection errors across 35 test files (audit run 5). The producing code is not at fault in the examples checked here: nine failures end in `ingest_pipeline.py:596 _list_current_source_ids`, which calls `list_source_record_ids(..., root_document_id=...)`; the current `BaseVectorstoreManager.list_source_record_ids` (`vectorstore_manager.py:401`) has that parameter and the test doubles do not (stale doubles, contract change `a61f091e3` / `ae14377c9`). The default `uv run` environment lacks the optional extras of the existing CI profile (`rag-guard.yml`: `--extra dev-ci --extra dev-ci-rag`). `tests/integration/rag/test_neo4j_live_qualification.py` has an `IndentationError` and is lost from every run. The static pre-context policy gate scans `intergrax/agents/uaep.py`, which was relocated (`pre_context_policy_audit.py:19`), so it has been red since 2026-09-20 and `test_ideal_w2_w2_script_gates` stops at the first failing script; `test_typed_sources_documented_on_provider_context` asserts a docstring phrase that no longer exists.
7. **Weak negative tests (F-D2-18).** `test_d2_compaction_roundtrip.py` (`except ValueError: return`, `except Exception: return`) and `test_d2_context_fidelity.py` (accepts "error or intact") can pass for the wrong reason.
