Parent: PDC-X implementation WBS (`PDC_IMPLEMENTATION_WBS.md`, batch **B-P7-D3**, wave W13). ## Problem

The declared-capability work of B-D3 is sound, but the audit found, and this plan re-verified, the following real defects:

1. **Three shipped streaming paths bypass the provider guard (F-D3-01, HIGH).** `BaseLLMAdapter._execute_streaming` (`base/base_llm_adapter.py:308-390`) runs `assert_protected_provider_call_allowed()`, the deadline check, `check_llm_tenant_quota`, rate limit / circuit breaker / retry through `execute_with_resilience`, the external-operation attempt and `stream_with_external_operation_lifecycle`, which registers the stream transport with the cancel seam. Seven adapters use it. Three do not and wrap the SDK stream only in `_provider_dependency_attempt()`, which holds a permit and does nothing else: `openai_responses_adapter.py:676` and `:778` (the registered default `openai` adapter), `gemini_adapter.py:218`, `:248`, `:412` (Vertex inherits them), `ollama_adapter.py:391` (LangChain Ollama). Effect: no protected-work/deadline guard, no tenant quota, no rate limit, no circuit breaker, no retry and no transport registration on those streams, while `registrations/external_operation_seams.py` declares `terminated` (OPENAI, GEMINI, VERTEX_GEMINI) and `transport_closed` (OLLAMA) for them. Latent today (no in-tree runtime caller of `stream_messages` / `stream_with_tools`, grep over `intergrax/`, `agents/`, `applications/`) but the declared capability is untrue for those paths. The R011 test registers a stream by hand and cannot see it: mutant M12 survives.
2. **Refusal / content-filter normalization is not fed on most paths (F-D3-02).** `normalize_refusal` is correct and tested, but streams and several buffered paths build the final response with the default finish reason: for example `openai_chat_completions_adapter.py:128-175` ignores `delta.refusal` and `finish_reason`; the stream paths of openai-responses, claude, mistral, gemini, bedrock, cohere, LangChain Ollama and native Ollama and the plain (non-tool) paths of gemini, cohere, bedrock and LangChain Ollama end as `COMPLETED` with empty content. The `SAFETY` / `guardrail_intervened` / `ERROR_TOXIC` vocabulary of `parse_finish_reason` has no producer on those paths. A refused streamed answer is indistinguishable from an empty successful one.
3. **Retry and failover misclassify by a class-name substring (F-D3-07, defect part).** `_is_retryable` (`_shared/retry.py:81-99`) returns true for any exception whose lower-cased class name contains `rate`, `timeout`, `connection` or `overloaded`; `GenerateContentError` (contains `rate` in "gene**rate**") and `SeparateTenantError` ("sepa**rate**") count as transient, so a non-transient error is retried and, with the default failover policy, the same request reaches the secondary provider (probe `probe_failover.py` of the audit). The absence of a typed taxonomy is a missing feature (Excluded findings); the substring bug in the existing classifier is a defect.
4. **The token estimator ignores assistant `tool_calls` (D2 finding F-D2-01, estimator half, D3-owned file).** `BaseLLMAdapter.estimate_tokens_for_messages` (`base/base_llm_adapter.py:632-668`) joins only `m.content`; `ChatMessage.tool_calls` (`list[dict]`), `name` and `tool_call_id` are not counted. A message with empty content and a very large `tool_calls[].function.arguments` estimates as ~0 tokens; `_execute_streaming` callers, usage accounting and `count_messages_tokens` under-report. The D2 planner does not touch this file (D2 ticket T-IGX-041-B covers the compiler, ladder and trim code in `intergrax/runtime/nexus/context/`); **this ticket owns the adapter estimator half and the D2 ticket may refer to it.**
5. **LangChain Ollama `stream_messages` silently re-issues the model call after a mid-stream failure (F-D3-08, LOW, by-product).** `ollama_adapter.py:413`: `except Exception:` falls back to `self.chat.invoke(...)` even after partial chunks were emitted, swallows the original error and emits the whole answer again. This method is rewritten for item 1, so the fix rides along (native Ollama already re-raises after a partial).
6. **Twelve stale or state-dependent `llm_adapters` unit failures and two collection errors (F-D3-05).** Reproduced at `1c864ea19` with the llm extras: 4 x `test_fixture_strict_adapter_parity` fail because `IncidentInvestigatorAgent` (`platform_proofs/scenarios/ai_incident_investigation/application/investigator_agent.py:171`) does not implement the abstract `Agent.run` (`intergrax/agents/agent_contract.py:25`), so `build_fixture_runtime_bundle()` cannot instantiate it at all: a product bug of the scenario fixture agent, not a test problem; 3 x `test_unsupported_tool_choice_rejects_before_provider` match a message that product code extended ("... 'auto', 'required', or a forced function choice"); `test_invalid_adapter_missing_model_fails_clearly` expects `LLMAdapterRegistrationError`, but `LLMAdapterRegistry.create` rejects the adapter earlier with a `TypeError` from the `LLMAdapter` runtime-protocol check (`model: str` is a protocol member), so the `AttributeError` branch of `_resolve_adapter_model_id` is unreachable through `create`; 4 tests (`test_missing_optional_llm_dependency_is_controlled`, 3 x `test_provider_creation_surfaces_dependency_error_without_sdk`) pass in isolation and fail in the combined run with SDK extras installed (the provider adapter module is already imported); `test_adapter_conformance.py` and `test_structured_output_flags.py` fail at collection without `anthropic`. The first eight were reproduced by the planning session; the four state-dependent ones and the collection errors are taken from the audit report and are re-reproduced by the implementer as the first test step.
7. **Overstating documentation (F-D3-03, doc part).** `LLMCallConfig` is documented as "Per-adapter call policy (timeouts, retries)", but `timeout_sec` is only used as an admission budget (see Excluded findings); the docstring is made precise.

## Deliverables

Pinned tests are written first and shown failing for the stated reason on unchanged code; then the fixes. No gate is narrowed, skipped (except where stated), xfailed or deleted.

### 1. Pinned regression tests (new files unless stated)

All new tests use fake SDK objects (no network, no credential, no real client); where an SDK is not installed in the default environment the test uses `pytest.importorskip` for that adapter only and the Test contract runs with the llm extras so nothing is skipped there.

1. `tests/qualification/pdc_x/d3/test_d3_f01_stream_guard.py` (F-D3-01, kills M12). For every shipped adapter class that has `stream_messages` / `stream_with_tools` (openai-responses, openai-chat, openai-compat/azure, claude, mistral, gemini, vertex-gemini, cohere, bedrock, native Ollama, LangChain Ollama), drive the real method with a fake SDK stream and assert: (a) with `assert_protected_provider_call_allowed` patched to deny, the call raises before the SDK is touched (fails today for openai-responses, gemini, LangChain Ollama); (b) `check_llm_tenant_quota` is consulted; (c) the stream transport is registered with the adapter's `_external_operation_stream_registry` for the operation id and closed in the end, and a consumer `close()` closes the underlying SDK stream; (d) negative: a raising SDK factory marks the external operation failed, and the permit of `_provider_dependency_boundary` is released exactly once on success, on mid-stream error and on early `close()`. Plus a source gate (AST) that fails when an adapter's stream method calls the SDK outside `_execute_streaming` (negative test on a synthetic adapter source).
2. `tests/qualification/pdc_x/d3/test_d3_f02_refusal_paths.py` (F-D3-02). A path matrix (adapter x method x signal) driven with fake SDK payloads that carry (i) a refusal text, (ii) a content-filter / safety stop, (iii) a normal stop and (iv) a length stop: expectations are `LLMFinishReason.REFUSAL` with the text, `CONTENT_FILTER` with no refusal text, `COMPLETED` and `LENGTH`; for stream paths both the FINAL event and the absence of a `COMPLETED` final on a refusal are asserted. Each (adapter, path) is a parametrized case so a missing producer is a named failure. A path whose provider API has no such signal on that call shape is listed in the test with a one-line reason and pinned as `COMPLETED` (so a later signal cannot be silently ignored); the implementer records that list in the checkpoint.
3. `tests/unit/llm_adapters/test_estimate_tokens_tool_calls.py` (estimator half of F-D2-01). Cases: empty-content assistant message with a 200,000-character `tool_calls[].function.arguments` estimates far above the 4 tokens of today; `name` and `tool_call_id` counted; negative/regression: messages without `tool_calls`, `name` and `tool_call_id` estimate exactly as before (a frozen table of inputs and expected counts from the unchanged code is committed first); a `tool_calls` value that is not JSON-serializable does not raise (falls back to `str`); estimation stays deterministic.
4. `tests/qualification/pdc_x/d3/test_d3_f07_retry_classification.py` (defect part of F-D3-07). Positives that stay retryable: `RateLimitError`, `APITimeoutError`, `APIConnectionError`, `ReadTimeout`, `OverloadedError`, status 429/500/502/503/504; negatives that must stop (fail today): `GenerateContentError`, `SeparateTenantError`, `MigrateError`, `AccelerateError`; the failover path with the default policy does not move such an error to the secondary provider; status 401 and cooperative cancellation still stop; `LLMRateLimitError` and the existing admission exceptions keep returning non-retryable.
5. `tests/qualification/pdc_x/d3/test_d3_f08_langchain_ollama_stream.py` (F-D3-08). Partial chunks followed by a transport error: the original error is raised, `invoke` is not called, no second answer is emitted; failure before any chunk still falls back to the buffered call once (current documented behaviour, kept).
6. `tests/qualification/pdc_x/d3/test_d3_f13_failover_precheck.py` (M03). A chain whose only member under-reports (`UnderReportingStreamAdapter`: declared `False`, streams anyway) is not selected for tool streaming by the failover pre-check, and the typed `LLMCapabilityMismatchError` is raised before any provider call; and a tightened `_declares_true` in `test_d3_r022_capability_flags.py` (existing file edited): accepts only a constant `True` or a delegation to a named flag; negative test with `return bool(self._x)` fails the gate. If the tightened predicate rejects a shipped adapter, the implementer records the adapter and keeps the old predicate for that adapter only through a named, commented allowlist entry, and reports it.
7. `tests/qualification/pdc_x/d3/test_d3_f03_timeout_admission.py` (honesty pin for F-D3-03). A call with an active execution deadline whose remaining budget is `<= 0` raises `ExecutionProtectedWorkDeniedError` before the SDK is called; the effective budget is the minimum of `timeout_sec` and the active deadline; a test states in its docstring that `timeout_sec` is not forwarded to the SDK (so a future enforcement ticket must change this test deliberately).

### 3. Product fixes (after the tests of section 1 are red for the right reason)

1. **F-D3-01.** Route the SDK stream of `openai_responses_adapter.py` (`stream_messages`, `stream_with_tools`), `gemini_adapter.py` (three stream sites; the buffered fallback of `stream_with_tools` is unchanged) and `ollama_adapter.py` (`stream_messages`) through `self._execute_streaming(factory)`. Design constraints: the factory only opens the SDK stream and returns an iterable; context-managed SDK streams (`responses.stream(...)`) are opened with `__enter__` in the factory and exited in the adapter's `finally`, with the opened stream kept in a closure so `get_final_response()` still works after the loop and the registered transport closes the same object; `_provider_dependency_attempt()` is removed from these paths only when nothing else uses it (it stays defined in the base class; the audit names no other user). `usage` begin/end semantics, event ordering and the FINAL event stay as they are.
2. **F-D3-02.** Read the provider stop signal per path and pass it to `build_adapter_response`: `delta.refusal` / `finish_reason` of OpenAI chat chunks, the response `status` / `incomplete_details` / refusal output item of OpenAI Responses (stream and plain), `stop_reason` of Claude, `finish_reason` of Mistral and Cohere, `finish_reason` and prompt-feedback block of Gemini, `stopReason` of Bedrock converse and invoke (including `guardrail_intervened`), `done_reason` of native Ollama, `response_metadata` of LangChain Ollama. Shared mapping helpers go to a new `intergrax/llm_adapters/_shared/stream_finish_signal.py` (pure functions, no I/O) or into the existing `_shared/openai_completion_mapping.py`; `normalize_refusal` and `parse_finish_reason` are not changed (their vocabulary already covers these values). SDK-specific shapes cannot be observed live (Path B): each mapping reads attributes through the existing `attribute_access.optional` helper, fails soft to the default only for a missing attribute (never swallows an exception), and the report names which shapes are modelled by fakes only.
3. **F-D3-07 (defect part).** `_is_retryable` classifies by whole words: the class name is split into CamelCase / underscore words and the tokens `timeout`, `connection`, `rate` (as a word or as `ratelimit`), `overloaded` must be words, not substrings. Nothing else in `retry.py` changes; no new error class is added.
4. **F-D2-01 estimator half.** `estimate_tokens_for_messages` appends the deterministic serialization of `tool_calls` (`json.dumps(..., sort_keys=True, default=str)`), `name` and `tool_call_id` of each message to the counted text; messages without them yield the same count as today.
5. **F-D3-08.** LangChain Ollama `stream_messages` re-raises when any chunk was emitted before the failure.
6. **F-D3-03 (doc part).** The docstring of `LLMCallConfig` states that `timeout_sec` is an admission budget (clamped to the active execution deadline; a non-positive budget is rejected before the call) and is not forwarded to the SDK; no field or behaviour changes.

Design constraints for the whole batch: no new registry, scheduler, engine, trust, policy or audit authority; nothing under `scripts/governance/`, `.github/`, `intergrax/contracts/` or `intergrax/applications/_shared/` changes (the F-D3-04 hotspot `intergrax/applications/_shared/llm_resolver.py` is **not** touched); no credential, endpoint or production configuration is added (C10/C15 freeze: no Docker migration, no new vendor integration); provider replaceability and the `intergrax/` -> `agents/` -> `applications/` layering are unchanged.
