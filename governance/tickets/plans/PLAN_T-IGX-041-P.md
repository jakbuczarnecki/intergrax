## Problem

1. **Ingest promotes the publication under a scoped key.** `IngestPipeline._run_source_replacement` builds `RagSourceOperationKey(tenant_id, namespace, workspace_id, source_id, publication_scope_id=str(native_docs[0].identity.root_document_id).strip())` (`intergrax/rag/ingest/ingest_pipeline.py:345-351`), acquires its lease (`:352`), indexes the chunks into the vector store and the graph (the graph block `:503-513`, `index_documents(native_chunks, chunk_ids=vector_ids)` at `:511`), then promotes the publication (`:527`). `RagSourceOperationKey` has the optional field `publication_scope_id` (`intergrax/distributed/source_operation.py:47`); when it is set it is part of `canonical_value` (`:70-71`) and so of `storage_id` (`:75-76`), and the in-process coordinator keys its dictionaries by the key object (`:138-140`, `active_publication_generation` at `:175-182`). A key with the scope and a key without it therefore address different publication records.
2. **The vector side resolves with the same scoped key.** `VectorstoreManager._filter_visible_publication_hits` builds the key from the hit's `provenance.source_id` and `identity.root_document_id` (`intergrax/rag/vectorstore/vectorstore_manager.py:345-360`, the root id read at `:353` and passed at `:359`) and decides visibility with `vector_record_visible` (`intergrax/rag/vectorstore/publication_visibility.py:14-31`: `active_generation is None` gives invisible, otherwise equality with the record generation).
3. **The graph side resolves with an unscoped key.** `InMemoryGraphStore._evidence` builds `RagSourceOperationKey(tenant_id=scope.tenant_id, namespace=scope.namespace, workspace_id=scope.workspace_id, source_id=str(metadata["source_id"]))` with no `publication_scope_id` (`intergrax/rag/graph/providers/inmemory_graph_store.py:343-348`); `graph_evidence_visible` (`intergrax/rag/graph/generation_visibility.py:48-68`) calls `coordinator.active_publication_generation(key=source_key)` (`:65`) and returns `active == generation` (`:68`), and `False` when the lookup raises (`:66-67`). `resolve_scope_active_generations` builds the same unscoped key for the Cypher path (`:82-87`), used by `visibility_query_params` (`:97-118`, call at `:110`). Because the promoted record lives under the scoped key, the unscoped lookup finds no publication (`None`), so every versioned graph evidence record is invisible. The audit reports the consequence for two tests, reproduced standalone: `test_graphrag_source_reingest_replaces_vectors_and_graph_safely` (`tests/integration/rag/test_graph_reingest_qualification.py:230`, failing with `assert set()`) and `test_stale_graph_topology_is_inactive_after_generation_takeover` (`tests/integration/rag/test_same_source_reingest_serialization.py:438`). Both use `InMemoryGraphStore` subclasses (`test_graph_reingest_qualification.py:129`, `:172`; `test_same_source_reingest_serialization.py:174`).
4. **The graph evidence carries no root document id, which is why the two files named by the auditor are not enough.** The evidence metadata comes from `HeuristicGraphIndexer._publication_metadata` (`intergrax/rag/graph/indexer/heuristic_graph_indexer.py:77-89`, called at `:51`, used for the nodes at `:60` and for the edges at `:72`): it emits `tenant_id`, `namespace`, `workspace_id`, `source_id` and, when the document holds it (`:85`), the publication generation (`SOURCE_PUBLICATION_GENERATION_METADATA_KEY`), and nothing else. `InMemoryGraphStore._evidence(chunk_id, metadata, scope, source_id)` (`:329-356`) and `resolve_scope_active_generations(coordinator, scope, source_ids)` (`:71-94`, with the source ids read from the evidence by `CypherRagGraphStore._scope_source_ids`, `cypher_rag_graph_store.py:145-153`) therefore have no value to pass as `publication_scope_id`. `SourceOperationCoordinator` (`source_operation.py:97-123`) has no lookup that ignores the scope. Amendment 1 of `DELEGATION-PDC-LOOP2.md` widens the write set by exactly the carrier file `heuristic_graph_indexer.py`.
5. **The root id is available to the indexer and equals the one used at ingest.** The chunks passed to the graph indexer are the `native_chunks` (`ingest_pipeline.py:511`), each carrying the generation in its metadata (`:422-429`) and an identity whose `root_document_id` equals the source document's (`intergrax/rag/document_splitters/chunk_document.py:56-58` rejects a chunk whose root differs; `:165` sets it from the source document). The ingest key uses `native_docs[0].identity.root_document_id`, the vector side uses the hit's `identity.root_document_id`.
6. The audit's fix instruction is: pass `publication_scope_id` from the source's root document id as `ingest_pipeline.py:350` and `vectorstore_manager.py:353` do (the two files live under `intergrax/rag/ingest/` and `intergrax/rag/vectorstore/`).

## Design

The graph side learns the root document id of each versioned evidence record and uses it as `publication_scope_id`, exactly as the vector side does. Nothing about the visibility law changes (`active == generation`, fail closed on `None` and on an error); only the key it is evaluated under.

1. **Constant and helper in the shared law** (`generation_visibility.py`): `GRAPH_PUBLICATION_SCOPE_METADATA_KEY: Final[str] = "root_document_id"` and `publication_scope_from_metadata(metadata: Mapping[str, object]) -> str | None`, which returns the stripped value when it is a non-empty `str` and `None` otherwise (a blank or non-string value is never turned into a key, because `RagSourceOperationKey.__post_init__` raises on an empty `publication_scope_id`, `source_operation.py:56-60`).
2. **Carrier** (`heuristic_graph_indexer.py`, `_publication_metadata`): inside the existing `if SOURCE_PUBLICATION_GENERATION_METADATA_KEY in doc.metadata:` block (`:85-88`) also set `metadata[GRAPH_PUBLICATION_SCOPE_METADATA_KEY] = str(doc.identity.root_document_id)`. The key is therefore written only for versioned documents; unversioned documents produce exactly the metadata they produce today. The nodes and the edges of the indexer both use this dictionary (`:60`, `:72`), so node evidence (`link_chunk` reads the node metadata, `inmemory_graph_store.py:167-178`) and edge evidence (`upsert_edge`, `:146-161`) both carry the id.
3. **In-memory store** (`inmemory_graph_store.py`, `_evidence`): the key at `:343-348` gets `publication_scope_id=publication_scope_from_metadata(metadata)`. The tenant, namespace and workspace of the key still come from the store scope (`scope`), never from the metadata; the source id still comes from the metadata as today.
4. **Shared Cypher helper** (`generation_visibility.py`): `resolve_scope_active_generations(coordinator, scope, source_ids, *, publication_scope_ids: Mapping[str, str] | None = None)` builds the key at `:82-87` with `publication_scope_id` from the mapping (keyed by the stripped source id; a missing, blank or non-string entry gives `None`, the unscoped key as today); `visibility_query_params(..., publication_scope_ids=None)` passes it through. `CypherRagGraphStore` is not changed and does not pass the parameter, so its behaviour is byte-identical (see residual R1).

**Why this does not widen visibility.** The scoped key can only select a publication record that was promoted under the same five fields (tenant, namespace, workspace, source id, scope id), because the key is compared as a whole (`source_operation.py:138-140`, `:70-76`). A different tenant, namespace, workspace, source or scope id addresses another record and resolves to `None` or to another generation, and `active == generation` is then false. A record with no scope id in its metadata keeps the unscoped key, which finds a publication only if one was promoted unscoped (the existing tests of `tests/unit/rag/graph/test_graph_generation_fencing.py` write such metadata: `_metadata` at `:58-72`, `_source_key` at `:33-39`, with no root id).

**Residuals (declared, not repaired by this ticket).**
- **R1 — Neo4j/Cypher store.** `CypherRagGraphStore` stores the whole evidence metadata as JSON (`:181`, `:196`) but its `RagEvidence` rows carry the scope fields, `source_id` and `generation` and no root document id (`:236`, `:296`), and `_scope_source_ids` returns source ids only (`:145-153`). With the carrier the JSON will additionally hold `root_document_id` for versioned documents, but the Cypher visibility predicate and `_visibility_params` (`:155-160`) still resolve unscoped. G-23 therefore stays open for the Neo4j path. Reopen condition: a fourth file (`cypher_rag_graph_store.py`: persist the id on `RagEvidence` and pair it with the generation in `active_pairs`) plus a live Neo4j qualification (`tests/integration/rag/test_neo4j_live_qualification.py` exists for it), which Amendment 1 of `DELEGATION-PDC-LOOP2.md` records as excluded by the C10/C15 restriction (`agent-env/rules/intergrax-env-vendor-qualification.md`, "Current C10/C15 restriction": no Docker migration, no new vendor integrations). The two reproduction tests use `InMemoryGraphStore` subclasses, not Neo4j.
- **R2 — other indexers.** `LlmGraphIndexer` and `CommunityReportGraphIndexer` write no source metadata (`llm_graph_indexer.py:70-71, 79-85`; `community_report_graph_indexer.py:54-64`, the only metadata is `summary` and `source_chunk_id`, `:59`), so their evidence is unversioned and always visible; unchanged.
- **R3 — several roots under one source.** The ingest key uses the root of `native_docs[0]` (`ingest_pipeline.py:350`) and the vector side filters hits by their own root (`vectorstore_manager.py:353`); the graph now behaves identically, so evidence of a document whose root differs from the promoted one is invisible, as its vector hit is. The mapping parameter of the shared helper holds one scope id per source for the same reason.

## Deliverables

Red for the right reason on the unchanged code (the positives fail because the scoped publication is not found; the negatives and the compatibility case are green before and after), then green:
   - **positive:** a publication promoted under `publication_scope_id=ROOT_A` for `SOURCE_A` makes edge and node evidence stamped with `root_document_id=ROOT_A` and the promoted generation visible (`find_nodes`, `node_ids_for_chunks`, `neighbors`);
   - **re-ingest:** a second generation promoted under the same scoped key hides the first generation's evidence and shows the second's;
   - **negative, wrong scope id:** evidence stamped `root-x` while the publication is scoped `ROOT_A` stays invisible;
   - **negative, missing scope id:** evidence without `root_document_id` while the publication is scoped stays invisible (fail closed);
   - **negative, other source:** evidence of `SOURCE_B` stamped with `ROOT_A` stays invisible while `SOURCE_A`'s evidence is visible in the same store (neither collapsed nor widened);
   - **negative, other tenant, namespace and workspace** (parametrized over `OTHER_TENANT`, `OTHER_SCOPE`, `OTHER_WORKSPACE` as defined in `test_graph_generation_fencing.py:28-30`, redefined locally): a store bound to that scope, holding evidence with the same source id, root id and generation, sees nothing, because the publication lives under the other scope's key;
   - **compatibility:** an unscoped publication and evidence without `root_document_id` stay visible (the pre-existing behaviour);
   - **shared helper:** `resolve_scope_active_generations` with `publication_scope_ids={SOURCE_A: ROOT_A}` returns the generation of a scoped publication; with a wrong id, a blank id or no mapping it returns `{}` for a scoped publication and still resolves an unscoped one; `visibility_query_params` passes the mapping through (`active_pairs` content);
   - **carrier:** `HeuristicGraphIndexer` run on a document built with `knowledge_document(..., metadata={SOURCE_PUBLICATION_GENERATION_METADATA_KEY: generation})` writes node and edge metadata containing `root_document_id` equal to the document's `identity.root_document_id`, and on a document without the generation key writes metadata without that key; and, end to end, the entities it writes are visible once the publication is promoted under that root and invisible under another root.
