# Cursor Direct Execution

<!-- igx:active:start -->
- Cursor defaults to one autonomous implementation agent. A contract labeled `CHATGPT_DIRECT_IMPLEMENTATION` with a canonical wave authorization selects the direct mode below. The top-level Composer is the sole executor; architecture, planning, scope, approvals, acceptance and certification are external.
- In this mode this Cursor-only rule controls role routing, execution and publication over generic shared AGENTS, DevOS role, autonomy, delivery, ticket checkpoint and PR instructions. All product boundaries, ticket approvals, mandatory tests, security, Git hooks and independent certification requirements remain in force.
- No Grok, subagents, orchestration, additional plan, separate reviewer or routine approval question in this mode. Execute the supplied contract sequentially in one session; do not load legacy orchestration or certification skills as execution prerequisites.
- Use the explicitly authorized isolated worktree and branch; keep the synchronized development checkout read-only as the trusted publisher location. The contract names the worktree, wave, base SHA, write set, ticket, tests and absolute publisher path. Never change or copy the publisher or authorization into the candidate.
- Before edits, run `python "<trusted-development-checkout>/scripts/cursor/igx_publish_candidate.py" --wave <wave> --preflight` from the named worktree. Proceed only on `PREFLIGHT_OK`. If a valid candidate already exists, resume remaining contract steps without repeating completed work.
- Implement only the authorized scope, run the specified mandatory tests and local quality gates, repair in-scope failures autonomously, and commit with exactly one `Ref: governance/tickets/T-IGX-<NN>-<L>.md` trailer. No AI attribution, scope expansion, test weakening or gate bypass.
- After commit and required local gates, run the same publisher command without `--preflight`. Do not substitute direct `git push`, direct `gh pr create`, legacy integrator or factory. The publisher reads `.cursor/publication/<wave>.json` from remote `development` and creates or reuses only the scoped draft PR. The external authority registers the authorization before dispatch; Composer never creates or edits it.
- Publication does not require prior independent review, a G6 verdict, a separate delivery role or a ticket lifecycle change by Composer. Target advancement is acceptable if the authorized base remains an ancestor. Do not merge, mark ready, change GitHub settings or declare certification.
- End with a compact report only after `PUBLISHED_DRAFT` confirms exact remote SHA and PR URL. If an actual mandatory control, access failure or out-of-scope conflict prevents completion, finish remaining safe work and report the exact failing command, exit code and error once. Preserve completed commits; never retry the old direct push path or ask for routine go-ahead.
- Outside this explicit mode, default to `development`. After the assigned tests and existing quality gates, fetch `origin/development` once, ensure the checkout and committed scope are correct, then run `git push origin development` as a standalone command from the actual development checkout. When the shell working directory is uncertain, use `git -C <absolute-checkout> push origin development` (quote paths with spaces) if the shell permits that form. Resolve routine in-scope failures autonomously and retry the authorized push. Verify the remote SHA; do not delegate publication to the Operator. Preserve foreign changes; report only actual unresolved access, conflict or mandatory gate failures with the exact diagnostic. If branch protection requires another path, use only an explicitly authorized mechanism. Direct gh mutations, force-push and protection bypass remain prohibited.
- Existing delegated role registry, separate G6/IIAC sessions and Operator-only decisions remain authoritative outside the direct execution contract. Software factory (`/igx-native-run-plan`, `igx_factory.py`) is voluntary tooling only on explicit Operator request; never a prerequisite for ChatGPT Direct Execution.
