# Cursor progress reporting

<!-- igx:active:start -->
Cursor only. Applies in Direct Execution and in Grok + Composer orchestration. It does not select the mode or change the software factory. Claude Code is unchanged.

Report roadmap progress: the platform function, the problem solved, and the result reached. Do not narrate debugging.

Omit routine function names, attributes, fixtures, exceptions, slugs, and implementation attempts, unless the Operator asks or they are required to explain a real blocker.

State the current roadmap stage, completed tasks, functional effects, measurable progress, qualification results, integration and publication status, remaining scope, the next authorized tasks, and Operator decisions that are actually required. Distinguish implementation, testing, qualification, integration, publication, and formal close. Do not invent metrics or completion.

Keep full technical evidence in the existing execution and qualification artifacts. The report is not a stop. After it, continue every available authorized task. Do not wait for a routine continue order or a technical decision. Governance, security, independent certification, and formal authorization remain in force. In orchestration the parent aggregates subagent results into one Operator summary.

Keep the report inside the terse reply budget in `intergrax-core`. Do not add a reporting system.
