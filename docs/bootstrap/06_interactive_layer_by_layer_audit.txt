## Per-domain work cycle (mandatory — do not skip steps)

For the **current domain only**:

### Step 1 — Read (narrow scope)

4. docs/audit/<DOMAIN>.md — domain audit prompt
5. docs/audit/README.md — shared production Harness checklist

Do **not** load unrelated domain pairs.

### Step 2 — Inspect code, tests, and gates (evidence required)

- Search and read source paths listed in docs/audit/<DOMAIN>.md
- Run domain-specific gate scripts and relevant pytest slices cited in the audit prompt
- Re-validate every "known open gap" from the audit prompt: closed / still open / partial
- Cite evidence as path:symbol, test name, or gate script output — no doc-only surveys

### Step 3 — Architecture audit vs ideal harness

For each audit dimension in the domain prompt, answer **Yes / Partial / No / Unknown** with evidence.

Explicitly assess against ideal harness qualities:
- Modularity and composability (no monolithic god-objects, no Tier-0 duplication)
- Plugin / entry-point extensibility for developers
- Policy-first execution where applicable
- Clarity and learnability for new implementers (scaffold, docs, single canonical paths)
- Scalability and operational readiness where in scope

Classify every gap: **P0 / P1 / P2 / P3 / P4** with **arguments** (why it matters, risk if ignored).
Mark: **intentional design boundary** vs **incomplete_wiring / missing wiring** vs **deferred product (§6.3)**.

### Step 4 — Plan vs implementation reconciliation

- Map plan rows (§6.1 queues, phase registers, gap IDs) to code reality
- Identify drift (plan says Done but code/tests disagree; audit says open but plan says closed)
- List open P0/P1 harness tasks; defer Phase K / §6.3 unless operator reprioritized

### Step 5 — Propose backlog tasks

Present a table of proposed plan tasks with: ID, priority, deliverable, acceptance criteria, add to plan? (yes/no pending operator).

Use naming convention when adding maintenance rows: `<DOMAIN-PREFIX>-MAINT-NN` or existing phase ID scheme in that domain plan.

### Step 6 — Output format (operator-facing)

Deliver the full audit using this structure:

1. Scope (audit-map layers covered)
